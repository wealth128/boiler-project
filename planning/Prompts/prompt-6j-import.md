# Prompt 6j for Claude Code: Downtime import (Google Sheets / Excel)

_Paste after 6i-3 is merged and pushed, BEFORE 7a (security review), so the review covers this too. Example of the file format: `planning/import-format/downtime-visits-template-EXAMPLE.xlsx` and `downtime-visits-EXAMPLE.csv`._

**Why:** if the system is down for days, offices write visits in a Google Sheet or Excel file. When the system is back, Admin imports that file so the reports are complete. This is NOT an import of old history (still out of scope).

```
Step 6j – Downtime import of visits from Excel / Google Sheets. Create branch step-6j-import. Rules: planning/security.md section 2, planning/rbac.md, the Encode rules (VisitRequest, StoreVisitRequest, duplicate-patient guard). Use maatwebsite/excel (already allowed); no new packages. Reuse the Encode validation and services; don't duplicate the rules.

The file format (one row = one visit), columns in this exact order, header row required:
Visit Date* (YYYY-MM-DD or a real Excel date) | Visit Time* (HH:MM 24-hour, or an Excel time) | Patient ID (P-000012, only for a returning patient) | Last Name* | First Name* | M.I. | Sex* (Male/Female) | Birthdate* (YYYY-MM-DD or Excel date) | Age (blank = computed from Birthdate on the Visit Date) | Branch* | Rank / Type* | Rank Other (specify) | Diagnosis* | Diagnosis Other (specify) | Category* (OPD/ER/Admission) | Remarks | Written by* (staff who wrote the row)
Headers may end with " *"; match them ignoring case, spaces and the star. Accept .xlsx (the "Visits" sheet, or the first sheet if there is none) and .csv (UTF-8, comma). Max 2 MB and 2,000 rows. Blank rows are skipped.

1. Download template (Admin only): GET /records/import/template returns an .xlsx built from the CURRENT lists, like planning/import-format/downtime-visits-template-EXAMPLE.xlsx: sheets "How to fill", "Visits" (headers + dropdowns for Sex, Branch, Rank / Type, Diagnosis, Category; date and text formats), "Example" (3–4 sample rows) and "Lists" (active branches, ranks per branch in seniority order, diagnoses with "Other (specify)" last, sex, category). Only active, not-in-Trash list items. File name census-downtime-template_YYYY-MM-DD.xlsx.
2. Import page (Admin only): "Records > Import" (GET /records/import), upload the file, then a PREVIEW before anything is saved:
   - Each row shows OK, Warning or Error with the reason in plain words and the row number from the file.
   - Errors (row can't be imported): missing required value; bad date/time; Visit Date in the future, before January 2026, or in a CLOSED month ("Reopen <month> first"); Birthdate after the Visit Date; age outside 0–120; unknown or inactive Branch, Rank (or a rank not in that branch), Diagnosis, Sex or Category; "Other (specify)" text missing, or given when the choice is not Other; text too long; Patient ID not found, in Trash, or whose name/birthdate don't match the row.
   - Warnings (row can be imported, Admin decides): no Patient ID but name + birthdate match an existing patient ("Will be linked to P-000012"; checkbox "save as a new patient instead", like Encode's duplicate guard); a visit for the same patient, same date and time and category already exists ("Possible duplicate visit", unchecked by default); the same patient twice in the file at the same date/time; a typed Other that matches a listed name ("Will count as <name>").
   - Summary at the top: N rows OK, N warnings, N errors.
3. Confirm import: imports only the rows chosen (OK rows + warnings Admin keeps). Rows with errors are never imported; Admin fixes the file and uploads again. Everything in one transaction with the same locks as Encode (new-patient lock). Each visit: visited_at = the file's date + time (Asia/Manila), encoded_by = the Admin who imported, a Visit No as usual, new patients get a Patient ID as usual; "Written by" is saved on the visit (new nullable column written_by, max 60) and shown in Records. Mark imported visits (new nullable column import_batch_id) and show a small "Imported" label in Records.
4. Import batches: new table import_batches (id, file name, original rows, imported count, skipped count, imported_by, created_at, undone_at, undone_by). A page section "Past imports" lists them (10 per page with the shared pagination).
5. Undo an import: Admin can move a whole batch to Trash in one step (reason "Wrong import", from the visit delete-reason list; add it if missing), only if none of its visits is in a closed month. New patients created only by that batch go to Trash too, unless they have other visits. Audit: import.created (counts, file name, no patient data), import.undone; each visit/patient also gets its normal created / moved-to-Trash entries.
6. Reports: imported visits count exactly like encoded visits (no change to ReportBuilder).
7. Access: role:admin + a new Gate import-visits; encoder, viewer and system_admin get 403 on every import route. Throttle upload/confirm/template (e.g. 10 a minute). The uploaded file is kept only until confirm or 1 hour (storage/app/private/imports, deleted after), never in public/, never in backups.
8. Docs: add "When the system is down" to docs/operations-guide.md and docs/troubleshooting.md (download the template NOW and keep a copy on each office PC and printed, write rows during downtime, then Admin imports), a user-manual section for Admin (draft), keyboard shortcuts if any. Put the template-download reminder on the custodian card list.
9. Pest tests: template has the right sheets, headers, dropdown lists from the current active lists; every error rule above; every warning; Excel date cells and text dates both work; closed month refused; preview saves nothing; confirm imports only chosen rows, all-or-nothing on a database error; linked vs new patient; Patient ID mismatch; duplicates; Written by saved; batch recorded; undo moves the batch (and only-batch patients) to Trash and is refused for a closed month; audit entries without patient data; 403 for the other roles; file size/row limits; CSV and XLSX; a row with formula text (=1+1) is stored as text.
10. When I approve, before the commit, update planning/project-history.md (section 0, section 5, decisions log: downtime import added; still no history import), planning/mvp-scope.md, planning/rbac.md (new permission), planning/database-schema.md (new table and columns), planning/setup-and-structure.md (routes), planning/security.md if relevant.
```
