## 1. The Project in Short
- **Problem:** the hospital's Admission/Admin office tallies patients by hand from Google Sheets every month for the Commanding Officer (CO).
- **Goal:** one centralized system. Offices **encode** each patient visit (OPD / ER / Admission), and the system **generates** monthly, quarterly, annual and custom-range reports automatically.
- **Where it runs:** one Windows server PC on the hospital LAN (Laragon), opened from office PCs by browser. No internet.
- **Repo:** https://github.com/wealth128/boiler-project (private). Folders: `planning/` (decisions), `planning/Prompts/` (every prompt sent to Claude Code), `prototype/prototype.html` (final screen reference), `system/` (Laravel app), `docs/` (keyboard shortcuts so far).

## 4. Decisions Log (what and why)

### Scope (Phase 1)
- Encoding fields: auto Patient ID, auto date/time, last name, first name, M.I., sex, **birthdate (encoded)**, **age (auto from birthdate, still editable)**, branch, rank (filtered by branch; "Others" = Dependent, Retiree, Civilian Employee, Civilian, Other (specify)), diagnosis (pick list + Other (specify)), category, remarks.
- **AFP serial number removed** (too personal).
- **Only ER encodes in v1.0.** OPD and Admission accounts are off. ER can choose any category.
- **Transfers:** no transfer screen. A transfer is a new visit in the new category, with a remark like "From ER, admitted to ward".
- **Counting:** each patient counted **once per category per period**; total visits shown as a separate line. A visit counts in the month it was encoded.
- **Diagnosis table is per visit and lists every diagnosis by name, typed Other text included; decided 2026-10-15.** It replaces "Top 10 + Others". Sex, Age range and Branch/rank stay per patient (latest visit).
- **Reports:** per category: total patients and visits, sex, age brackets, diagnosis (per visit, every diagnosis by name), Branch × Rank. Formats: screen, PDF, Excel, print. Header: hospital name/logo, period, Prepared by, Noted by: Commanding Officer.
- No import of old Google Sheets. Not in v1.0: discharge, transfer tracking, bed census, dashboards.

### Roles & access
- Roles: **encoder**, **admin** (only one active), **system_admin** (accounts only, no patient data, only one active), **viewer** (CO, reports only).
- Encoder edits **own visits, same day only**. Admin edits any. Nobody edits a **closed month**.
- Login by **username**; 5 wrong passwords lock the account; 10 tries/minute limit.
- **Temporary password** after create/reset must be changed at first login. Resetting asks for the resetter's own password.
- Deactivated / locked / deleted users are signed out on their next click.
- **Everyone is signed out daily at 8:00 PM** (Asia/Manila). No idle timeout. ER night shift logs in again.
- Password rule: at least 8 characters, letters and numbers (works offline; no internet check).
- Admin account protected: System Admin can't edit/reset/deactivate it; nobody changes their own role; IT has `php artisan census:reset-admin-password`.

### Data safety
- **Soft delete → Trash** for visits, patients, users, diagnoses, ranks, age brackets. Permanent delete only from Trash, by Admin, typing the ID.
- Permanent delete is blocked when: the month is closed; a patient still has visits; a diagnosis/rank is used by a visit; a user has visits or audit entries.
- A patient goes to Trash only after all their visits are in Trash. A visit can't be restored while its patient is in Trash.
- **Delete reason is a dropdown per record type** (added 2026-10-14 so people can't type "asd"):
  - Visit: Duplicate entry · Wrong patient selected · Encoded by mistake · Test / training entry · Other (specify)
  - Patient: Duplicate patient record · Encoded by mistake · Test / training entry · Other (specify)
  - User: Resigned / separated · Transferred out · Created by mistake · Other (specify)
  - List item: Duplicate item · Misspelled, replaced with a corrected one · No longer used · Other (specify)
  - Month report: Encoded in the wrong month · Test / training data · Other (specify)
  - "Other" needs 10–200 characters, saved as "Other: <text>". Checked in TrashService on the server.
- **Close month** (only after the month ends) saves a report snapshot and locks edits. Reopen removes it. **Delete month report** moves all its visits to Trash as one item.
- **Audit log** records every change; can't be edited; never logs passwords.
- **Daily backup** at 02:00, kept 30 days, each run recorded. Logs: one file per day, kept 30 days.
- **Backup screen (6g, decided 2026-10-16):**
  - **Red warning** when the last run failed, or there is no successful backup in the last **26 hours** (daily run plus a 2-hour margin). It shows on the Backups page in full, and as a short line with a link at the top of every Admin page. Never shown to other roles.
  - **No download and no restore from the browser.** Backup files hold all patient data, so they stay in the backup folder and IT copies them (weekly USB copy, monthly test restore).
  - **USB copy and test restore marks** (new table `backup_marks`: who, when). Admin marks each with a confirm step; each mark is audited. A yellow warning shows on every Admin page when no USB copy was marked in **8 days** or no test restore in **35 days** (never marked counts as overdue). They are **reminders only and never block any work.**
  - The warning banner is **hidden on /backups** itself, because the status panel shows the same warnings in full.
  - **Run backup now** runs `BackupService` once behind a lock shared with the scheduler and `backup:run` ("A backup is already running."). It writes the audit entry `backup.run_manual`.
  - Error text on screen hides the database password and login. `mysqldump` gets `SystemRoot` explicitly on Windows, or it fails with "Can't create TCP/IP socket (10106)" when started from the web server.

- **Self-setup and self-care (6i-1, decided 2026-10-18):**
  - **Every backup has two files:** the database dump and a zip of `storage/app/private` (logo, signatures, frozen signature folders) with the same date stamp (`patient_census_files_YYYY-MM-DD_HHMMSS.zip`). A run is **Success only if both were written**; if either fails, both are deleted and the run is Failed. The 30-day cleanup removes old zips too. `backup_runs` keeps `zip_name` and `zip_size_bytes`; the Backups page shows both files.
  - **Scheduler heartbeat bar:** the scheduler saves a "last ran" time every minute. Older than 5 minutes (or never), Admin sees a red bar on every page with a link to System health. It is a separate shared prop (`schedulerAlert`), Admin only.
  - **System health page:** Admin only (`/system/health`, `view-health` Gate, role:admin; other roles get 403). 11 checks as OK / Warning / Problem with one "What to do" line. Shows no passwords, `.env` contents or connection details. `php artisan census:health` runs the same checks and exits 1 on any Problem.
  - **`census:install`** (`--repair` for an installed system), **`census:update`**, **`census:restore {file}`**: the MySQL root password is typed hidden and kept in memory only; never in `.env`, logs or the audit log. `census_app` gets only SELECT, INSERT, UPDATE, DELETE, LOCK TABLES, SHOW VIEW, TRIGGER (`planning/security.md` section 4). The dev seeder never runs.
  - **The 8 small decisions Claude Code made, approved:** (1) update and restore ask for the root password before `down`, so a typo never leaves the site in maintenance mode; (2) restore drops and recreates the database before loading; (3) restore deletes all sessions afterwards, so everyone logs in again; (4) the restore safety backup skips the 30-day cleanup, so it cannot delete the file being restored; (5) if update or restore fails, the site stays in maintenance mode on purpose and the command prints the next steps (`php artisan up`, or `php artisan census:restore <safety backup>`); (6) caches are rebuilt in a new PHP process so they read the new `.env`; (7) the install asks every question first, then changes things; (8) `census_app` is created for `localhost` only, with a login test at the end.
  - **Temporary MySQL login file** (only when loading a backup): written to the system temp folder, never under `storage/app/private` (it is zipped into backups), owner-only, deleted in a `finally` block even when loading fails. Tested.

- **Review fixes after 6i-1 (6i-1-fix, decided 2026-10-19):**
  - **Remember me is always off.** The login page has no checkbox, and the server now ignores a hand-made `remember=1`, so no long-lived cookie exists that could survive a password reset or the 8 PM sign-out. `remember_token` also changes whenever a password is set or changed (Admin reset, IT reset, own change, first-login change), so any old cookie stops working.
  - **Restore checks before it deletes:** the dump must be readable and end with mysqldump's "-- Dump completed" line ("This backup file is incomplete. Choose another one."), the mysql program must start (`mysql --version`, else it asks for the path, Enter cancels) and the picture zip must open. All of this happens before the `RESTORE` question, the safety backup, maintenance mode and `DROP DATABASE`, so a bad file never costs the live data. After a restore, the sessions, `cache` and `cache_locks` tables are cleared too (old locks and the old scheduler heartbeat must not come back).
  - **Install never runs over a live system by mistake:** it refuses when `.env` has an `APP_KEY`, when users exist, or when the `patient_census` database exists, even if the database login fails. Only `--force` plus typing `INSTALL OVER` goes on. `census:install` also finds the mysql program next to mysqldump and saves it as `MYSQL_PATH` (`--repair` adds it to older installs), and System health shows a "MySQL program (for restore)" check (Warning only).
  - **One month lock per year** (`month-close:YYYY`) is used by close and reopen, so two months of one quarter closed together still make the quarter and year snapshot and a reopen cannot race a close. The duplicate-patient lock key uses ASCII-folded, lowercased, space-collapsed names, the way MySQL compares them ("Peña" and "Pena" share one lock). Both waits come from `census.lock_wait_seconds` (5).
  - **The scheduler time shown on System health is in Asia/Manila**, not UTC.
- **Windows scripts (6i-2, decided 2026-10-19):**
  - **Files** in `system/scripts/windows/`: thin wrappers that run the 6i-1 artisan commands. Each one checks "Run as administrator" (and says so in plain words), finds Laragon's `php.exe` (asks if not found, remembers it in `php-path.txt`, not committed), writes start and end lines (never secrets) to `storage/logs/scripts.log`, and ends with "Press any key to close...". Shared helpers: `_common.bat`, `_services.bat`, `run-scheduler.bat`, four small PowerShell files. `.bat` and `.ps1` are forced to Windows line endings in `.gitattributes`.
  - **MySQL and Apache run as Windows services** `CensusMySQL` and `CensusApache` (not a start-up task, not Laragon's tray): registered from Laragon's own `my.ini` and `httpd.conf`, automatic (delayed) start, restart on crash (3 tries, 1 minute apart). `install.bat` also checks `bind-address=127.0.0.1` in `my.ini` (keeps a `.bak` first), writes `sites-enabled/00-census.conf` (loads first, answers for any name or IP, serves `system/public`), checks Apache's syntax first and rolls the file back if it fails, turns off Laragon's own auto-start (best effort: only keys that exist), and checks that `http://localhost/` shows the login page. **Never click Start All in Laragon on the server** (printed by the install, written in the operations guide and troubleshooting). If a Laragon file is missing it stops with: open Laragon once, Start All, Stop All, close it, run `install.bat` again.
  - **Scheduler task "Census - Scheduler"** runs `run-scheduler.bat` every minute with nobody logged in. It runs as SYSTEM when `BACKUP_PATH` is a local folder, or as a Windows account (Windows asks for the password) when `BACKUP_PATH` is a network share, because SYSTEM cannot sign in to another PC. The install warns to use an account whose password never expires, and right after creating the task runs one real backup through it (a flag file makes `run-scheduler.bat` run `backup:run` once) and shows success or failure. A Windows password change breaks backups until `install.bat` is run again (troubleshooting entry).
  - **Firewall:** web port (80, a constant in `_common.bat`) open to the local subnet only; 3306 blocked from outside. `install.bat` run again on an installed system runs `census:install --repair` and re-creates services (only if missing), task and rules; it never touches data. `uninstall-tasks.bat` removes the task, both services and the firewall rules only.
  - **Why Windows services, not a start-up task (decided 2026-10-19):** a service starts with Windows with nobody logged in and Windows restarts it after a crash (`sc failure`); a start-up task would not restart it, and Laragon itself is a tray program that needs a logged-in user. The cost: never click Start All in Laragon on the server.
  - **Why SYSTEM for a local backup folder and a Windows account for a network share (decided 2026-10-19):** SYSTEM has no network login, so it cannot write to the backup PC. The account's password is saved inside the task, so it must never expire; after a password change `install.bat` is run again with the new password (troubleshooting entry). Proven at install time by one real backup run through the task.
  - **Requirements doc (decided 2026-10-19):** `docs/requirements.md` lists what to install first (server part, developer part, how to build the ready-to-install folder: clean clone, `composer install --no-dev --optimize-autoloader`, `npm ci`, `npm run build`; no Composer, Node.js or Git on the server). `install.bat` runs `check-requirements.ps1` before anything changes: Windows 10/11 64-bit, 4 GB memory, 10 GB free disk, Visual C++ Redistributable x64 (registry), Laragon with MySQL 8 and Apache, PHP starts and is 8.4.1+ and Thread Safe, port 80 free. `census:install` then checks the PHP extensions, folders, upload limits and MySQL as before.
  - **Not yet proven:** none of this has run on a real Laragon server. The manual test list is `docs/windows-scripts-manual-test.md`.

### Downtime import (6j, decided 2026-10-20 and 2026-10-21)
- **Added to v1.0:** when the system is down, offices write visits in a spreadsheet and Admin imports the file afterwards (Records > Import), so the reports are complete. **A history import (old Google Sheets) is still out of scope.**
- **Admin only** (`import-visits` Gate + `role:admin`). Encoder, Viewer and System Admin get 403 on every import route. Imported visits have the Admin as `encoded_by` and the staff name from the file as "Written by" (new column `visits.written_by`, max 60), with an "Imported" label in Records. Reports count them like any other visit (no change to ReportBuilder).
- **File:** one row = one visit, 17 columns in a fixed order, header row required; `.xlsx` (sheet "Visits", else the first) or `.csv`; 2 MB and 2,000 rows. More rows, or data below row 10,000, are refused with "Split it into smaller files" instead of being cut. The template is built from the current lists (sheets How to fill, Visits, Example, Lists).
- **Preview first, nothing saved until confirm.** Each row is OK, Warning or Error in plain words. Errors are never imported. Warnings are decided by Admin: linked to a patient with the same name and birthdate ("save as a new patient instead" only counts for a row that has this warning), possible duplicate visit (unticked by default), same patient twice in the file, typed Other that matches a listed name.
- **Closed months are refused**, in the preview and again at confirm: confirm and undo take the same per-year lock closing a month uses (`month-close:YYYY`) and read the closed months again inside the transaction, so a month closed meanwhile refuses the whole import.
- **Whole import refused if a list item or month changed meanwhile:** branch, rank and diagnosis are re-read with a lock inside the transaction. One that went to Trash or was turned off since the preview refuses the import ("Nothing was imported"), as does a patient that changed.
- **New-at-confirm duplicates are held back:** a row that has a possible-duplicate warning at confirm that was not in the preview (the visit was saved meanwhile, for example on Encode) is not imported, and its row number is listed in the result. A duplicate that was in the preview imports if it was ticked. The rest of the rows are imported.
- **One import per file:** the staged file is claimed atomically (lock `import-confirm:<token>` + rename); a second confirm says "This file was already imported." and saves nothing. A failed import gives the file back. The file waits at most an hour in `storage/app/private/imports` (random name, only for who uploaded it, never in `public/` or in a backup); a cleanup runs every 15 minutes.
- **CSV:** UTF-8, but a CSV that is not valid UTF-8 (Excel's plain Windows "CSV") is converted from Windows-1252 first, so Ñ survives. The template says: in Excel save as CSV UTF-8; .xlsx is best. An .xlsx that is over 20 MB once unpacked (a sheet formatted down a million rows) is refused with "This file is too large to read" before it is read.
- **Speed and limits:** the lists, the patients named in the file and the visits that could be duplicates are read once for the whole file (2,000 rows take fewer than 50 queries, tested); the checked preview is kept beside the file and re-checked when closed months, lists, patients or visits change, and always at confirm. Request limits per user: **60 a minute** for opening the Import page and paging Past imports (`import-page`); **10 a minute** for template download, upload, confirm, cancel and undo (`import-actions`).
- **Past imports and Undo:** `import_batches` (file name, counts, who, when, undone). Undo import moves every visit of the batch to Trash with the reason "Wrong import", and the patients only that batch created (unless they have other visits), refused while any of its visits is in a closed month. Audit: `import.created` (counts and file name, no patient data) and `import.undone`, plus the normal entries for each record.
- **Template download was slow** (about 1 s, 83 KB): formats are now set per column instead of per cell (about 0.14 s, 13 KB).

### Security review (7a, decided 2026-10-21)
- **Test everything from the route list, not from a hand-made list:** `RouteAccessMatrixTest` reads `Route::getRoutes()`; a new route with no entry fails until someone writes its answer from `planning/rbac.md`. Seven senders: signed out, the four roles, an Admin with a temporary password and a deactivated Admin.
- **Routes outside `rbac.md`** (`/`, `/login`, `/logout`, password confirm, `/settings`, `/up`, `/storage/*`, not found) now have written answers in `planning/rbac.md`.
- **Security headers on every response** (`SecurityHeaders` middleware: `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Content-Security-Policy`). The CSP is strict for scripts (own server plus a per-response nonce, no `unsafe-eval`) and keeps `unsafe-inline` for **styles only**, because the interface and a toast library set styles while running. A response that sets a stricter policy itself (the pictures) keeps it. The Vite dev server is allowed only while `npm run dev` runs and never in production. No HSTS header until HTTPS is decided.
- **Cookie:** `http_only` and `same_site=lax` fixed in the code; `Secure` from `SESSION_SECURE_COOKIE` (default off).
- **`'serve'` follows `APP_ENV`:** no `storage/{path}` route in production, so the manual Phase 8 step is gone.
- **Ids in addresses are at most 18 digits.** A longer number is "not found".
- **Anything that can arrive as a list** (`name[]=x`) must be checked as text before it is cleaned or cast. The tamper tests send lists to every field.
- **Logs are cleaned** of secrets by a formatter wrapper on every file channel; a failed backup's error text is cleaned before it is saved.
- **Laravel 13 CSRF:** a request is accepted with the token or when the browser says it is "same-origin"; a script with no token and no such header gets 419. The session cookie is SameSite=Lax as well.
- **Test rules learned:** global helper functions in test files share one namespace (give new ones a prefix); in Pest datasets a value that is an array is spread into arguments (wrap it in another array); a `Visit` or `Patient` created already in Trash gets no number (create it, then trash it).
- **Left open on purpose:** a user with a temporary password gets "not found" for a record number that does not exist (the record is looked up before the redirect): no data is exposed.

### Pagination (7b, decided 2026-10-23)
- **One shared footer, changed once and used everywhere:** `TablePaging` (server) and `components/shared/pagination.tsx` (client). Every long list uses it: Records Visits and Patients, Past imports, Trash, Audit log, Backups history, User accounts and System health.
- **Rows per page:** default 10, choices 10 / 20 / 50, kept in the address as `?per_page=`. The server accepts only those three; anything else (text, a list, 999) is 10. Changing it goes back to page 1 and keeps the filters. A page past the end goes to the last page.
- **At most 3 page numbers** around the current page (4 5 6; 1 2 3 at the start; last three at the end), plus « First, ‹ Prev, Next ›, Last ». The three numbers are worked out in PHP (`TablePaging::window`, sent as `meta.pages`) because the project has no JavaScript test runner.
- **Page jump:** "Page [ ] of N", a dropdown up to 200 pages, a number box with Go beyond that. The current page has `aria-current="page"`. On a phone only Prev, "Page x of N" and Next show.
- **User accounts are paged** (10 per page, by name). Add, edit, unlock, reset, deactivate and Trash return to the page the user was on (`back()` with the users list as the fallback).
- **System health:** Problems first, then Warnings, then OK (order of the checks kept inside each group), so page 2 never hides a problem. A Show filter (All / Problems / Warnings / OK, `?status=`, unknown values mean All) and the same paging. The top line says "N problems, N warnings" and always counts every check.
- **Left unpaged on purpose:** the import preview (client-side, has its own filter), the Dropdown Lists panels (short, admin-managed) and the report sheets. There is no test-restore history list, only the latest result.
- **Reports: Year dropdown for the monthly period (screen only).** Period type, Month, Year. Year decides which months the Month list shows; changing it keeps the same month when that year has it. The server still receives `month=YYYY-MM`, so Print, PDF and Excel did not change.
- **Test rule learned:** the test files in this project use Windows line endings, so a multi-line text replace can silently miss: use single-line edits there.

### Fixes from the general check (7d-4, decided 2026-10-23)
- **Report data version counter instead of a table checksum.** `ReportCache` keys a built report on period + `ReportBuilder::VERSION` + one number, the "report data version" (row `report_data_version` in `settings`, read with one primary-key query, `ReportDataVersion`). The `BumpsReportVersion` trait raises it on saved (only when something changed), deleted, restored and force-deleted of Visit, Patient, Branch, Rank, Diagnosis, AgeBracket, MonthClosure, ReportSnapshot and ImportBatch. Paths that skip model events raise it by hand: reopen and re-saving a snapshot (query deletes), Delete month report, its restore and its permanent delete, and `census:restore` (which also empties the cache). The increase happens inside the change's own transaction, so a rollback leaves it alone. **Why:** `CHECKSUM TABLE` read every row of 8 tables on every report request, briefly locked them (encoders waited) and got slower every year. **Accepted cost: a change made by hand in MySQL, outside the system, is not noticed until the 1-hour cache expires.**
- **Nightly cache clean-up:** `CacheCleaner` deletes expired rows of the cache and cache_locks tables every day at 1:30 AM (scheduled task `cache-purge-expired`). Laravel never removes them itself.
- **Backups skip throwaway data:** the dump leaves out the rows of cache, cache_locks and sessions (`--ignore-table`), and a second small `mysqldump --no-data` run adds only their structure to the end of the same file, so a restore finds the tables, empty. Either dump failing fails the backup and removes the partial files. Table names come from the config (`BackupService::throwawayTables()`).
- **Page clamp:** `TablePaging::page()` keeps `?page=` between 1 and 100000 (anything that is not a plain number is 1); it is also Laravel's page resolver, so every `paginate()` is covered. A huge number goes to the last page instead of a 500.
- **Log cleaner widened:** any name that contains password, passwd, token or secret (`password`, `DB_PASSWORD`, `RESTORE_TEST_PASSWORD`, `remember_token`, `token`) is cleaned as `name=value`, `name: value` or JSON (`"password":"x"`), also when the JSON sits inside a JSON string and in nested context arrays; non-text values and odd configuration values cannot make it fail.
- **Public logo without a session:** `/hospital-logo` no longer runs the session, cookie, CSRF or app middleware, so it sets no cookie; the throttle and the global security headers stay. A signed-in user with a temporary password or a deactivated account also gets the logo (it is public).
- **HSTS only on HTTPS:** `Strict-Transport-Security: max-age=31536000` (this host only, no subdomains, no preload) is added only when `$request->isSecure()`, so it is ready if HTTPS is chosen and does nothing on plain HTTP.
- **`php artisan census:rebuild-snapshots`:** for Admin or IT on the server; shows how many saved copies there are and how many are in an older version, asks to type REBUILD, then recounts every month, quarter and year copy at the current `ReportBuilder::VERSION` in one transaction under the year locks, keeping each period's frozen signature block, author and date. Audit entry `snapshots.rebuilt` (count, version). Not needed on a fresh server; for use after a future version bump. In `docs/operations-guide.md`, section 10.
- **Test rule learned (again):** run only one `php artisan test` at a time; two runs on `patient_census_test` together deadlock and drop tables under each other.

### Charts, report speed and the daily census (7d-3, decided 2026-10-23)
- **Charts sit above the table they come from.** Summary: daily census, Male vs Female (one 100% bar), age range by sex (pyramid, males left, females right, oldest at the top), top 10 diagnoses, branch of service (Army, Navy, Air Force, Marines, Others), this period vs previous (left out when there is no earlier period). Each category: daily census and top 10 diagnoses. The charts read the report tables (and the report's daily census), never recount, so a chart cannot show a number its table does not; a closed month's charts come from its saved copy and never change.
- **Server-drawn SVG, native Excel charts, no new package.** One PHP chart builder (`ChartSvg`, data in `ReportCharts`) makes a flat 2D SVG used by the screen, Print and PDF; a wide drawing (640 units) and a narrow one (280 units) so text stays 12 px or more on a 360 px phone (about 10 pt in the PDF). Excel gets native PhpSpreadsheet charts that read their own table's cells. The age pyramid is side by side bars in Excel (a mirrored one needs helper cells). Each Excel chart has reserved rows above its table, titles, number labels and the same colors; a page break is estimated above a chart that would not fit the rest of a printed page.
- **Colors (fixed, from the navy theme):** OPD `#8FB4E3`, ER `#1F3864`, Admission `#2E8B72`, Male `#27508C`, Female `#F0A93B`, single series `#3A5A8C`, this period `#1F3864` and previous `#AEB9CC`. They differ strongly in brightness (tested), every bar has its number beside it and there is a legend with more than one series, so black and white print still works. Zero data shows "No visits in this period". Each SVG has role="img" and an aria-label summary; bars take focus and show their exact value.
- **Daily census shows the chart and totals only (decided 2026-10-23):** the table has one row (OPD, ER, Admission, Total visits) and "Busiest day: DD-Mon-YYYY (n visits)". A quarter or year keeps its by-month rows. The day figures are in the chart; in Excel they are on a very hidden last sheet "Chart data" that the chart reads (`ChartDataSheet`). The PDF went from 29 to 23 pages on the sample.
- **No raw HTML on screen:** `svg-tree.ts` keeps only svg, g, rect, line, path, text, tspan, title and desc with checked geometry and style attributes, and drops on* handlers, href and xlink:href, style with url() and every other tag. A diagnosis named like `<script>` shows as text. Its tests run in vitest and are started by `tests/Feature/Security/SvgChartWhitelistTest.php` inside `php artisan test`. The PDF needs `PdfSvg`: dompdf's SVG text otherwise inherits whatever font the page used before, so charts came out bold or plain at random.
- **Window-function counting (MySQL 8 required, already in docs/requirements.md):** each patient's latest visit (latest time, then highest id) comes from two `ROW_NUMBER()` queries (per category, and overall) counted in PHP, instead of 11 slow correlated queries. A test keeps the old method as a reference and compares patients, visits, sex, age ranges, branch and rank, and new vs returning on every month, quarter and the year of a seeded year, with ties, deleted visits and edge minutes: identical. A full monthly, quarterly and annual report runs fewer than 40 queries, and the count does not grow with the data (tests).
- **Report cache with a data-changed stamp (`ReportCache`):** an open period's built report is kept up to one hour under period + `ReportBuilder::VERSION` + a stamp, the checksum of visits, patients, branches, ranks, diagnoses, age_brackets, month_closures and report_snapshots (`CHECKSUM TABLE`), so any change, even by hand in MySQL, counts again. Closed periods use their saved copy. The "Generated" time on a remembered screen is when it was counted.
- **Excel and PDF speed:** styles are applied to whole ranges by look (a few dozen cell formats instead of hundreds), no formulas, reused styles. PDF: `storage/fonts` exists (with a .gitignore), the logo is shrunk to 160 px high before embedding, fonts are not subsetted (faster; the PDF is about 1.3 MB). Export buttons fetch the file in the background and show "Preparing the file…" with both file buttons off.
- **Measured before to after (dev PC, 28,470 visits in 2026, each request in a fresh PHP process, seconds; "after" is the first request, then the same period again from the cache):**
  - Open monthly: screen 1.5 to 0.33 (0.22), Print 1.4 to 0.30 (0.11), PDF 2.3 to 1.8 (1.7), Excel 5.0 to 0.76 (0.62).
  - Open quarterly: screen 4.1 to 1.0 (0.10), Print 4.2 to 1.0 (0.21), PDF 5.1 to 2.3 (1.3), Excel 6.9 to 1.2 (0.52).
  - Open annual: screen 13.1 to 2.0 (0.11), Print 12.2 to 1.7 (0.11), PDF 11.1 to 3.6 (1.4), Excel 16.2 to 2.0 (0.64).
  - Closed (saved copy): screen and Print under 0.2 before and after; PDF 1.2 to 1.6 before, 1.4 to 1.5 after; Excel monthly 6.6 to 0.6, quarterly 6.1 to 0.4, annual 5.9 to 0.44. Targets met (monthly export under 3 s, annual under 8 s). Charts cost about 3 ms to build. PDF time is mostly dompdf laying out the pages, so it barely changed.
  - Top causes found: 11 slow latest-visit queries (about 0.9 s each on a year), Excel cell-by-cell styling (about 7 s), every format recounting from zero. The dompdf font cache folder was missing.
- **`ANALYZE TABLE visits, patients` after `census:restore` and after a confirmed import (`TableStatistics`):** right after a bulk load MySQL's statistics are stale and the first report ran a very slow plan (43 s monthly; 227 s once in the first run). The service is skipped inside an open transaction (ANALYZE ends it, which broke the test transactions), a failure is only logged. Tests: called once after a restore (after the connection is refreshed, before the system comes back up), called once after a confirmed import, not called when the import is refused.
- **Gotchas:** the `report-files` rate limit (Print, PDF, Excel) gives 429 in a measuring script; php-svg-lib cannot set bold for a font it does not know; long shell here-documents fail on the dev PC, so write big files with an editor.

### Report content (7d-2, decided 2026-10-23)
- **One source for every format.** `ReportBuilder` counts; `ReportSections` turns a report (live or saved) into tables (title, columns with a type, rows with a style, note); the screen, Print, the PDF and the Excel file all draw those tables, so they cannot differ. The screen and Print get them as the `sections` prop.
- **Summary counts each patient once across categories**, using their latest visit in any category (sex, age by sex, branch, ranks, AFP split, new and returning). This is the same rule as the grand total, so the Summary total can be lower than the three categories added together; the page says so. Diagnoses and the daily census count visits.
- **Summary content:** patients and visits, sex, age range by sex, Top 20 diagnoses, branch of service (with % and AFP personnel against Others by the branch's `is_afp` flag), ranks by branch with subtotals, new and returning, daily census, comparison with the previous period.
- **Top 20 on the Summary only.** It has no "Others" line and no total and carries the note "Full list on each category page." **Every diagnosis stays on each category page** (highest count first, ties by name, with the % of the category's visits and a total row that equals Visits).
- **New against returning:** of the patients counted, new = no earlier visit (not in Trash) before the period. On a category page the earlier visit must be in that category (a patient seen in ER last month is new in OPD); on the Summary, in any category.
- **Daily census:** one row for each day when the period is 31 days or fewer, otherwise one row for each month (quarters, years and custom ranges over 31 days). Days and months with no visits are listed. The busiest day (or month) is named; a tie names the earlier one.
- **Previous period:** a whole number of months (month, quarter, year) is compared with the same number of months before; any other range with the same number of days before. Left out when that period starts before 1 January 2026 (`ReportBuilder::EARLIEST_DATA`). Counted with the same rule as the grand total. Percent change is a dash when the earlier figure is 0.
- **`ReportBuilder::VERSION` is 4.** A closed month, quarter or year saves the new sections and the previous-period figures, so a correction made later does not change it. A copy of an older version (only on dev PCs) is counted live and the report says "Not final – no saved copy"; before this, a closed month with an old copy wrongly said Final.
- **Screen:** each table is a collapsible panel (`<details>`, open at first). Printing the screen (Ctrl + P) always shows every panel open: folded panels are opened on `beforeprint` and folded again on `afterprint`. The Print view draws the tables plain. Tested by checking the code, since a print dialog cannot be driven from a test.
- **PDF:** each table is kept together on one page where it fits. **Excel:** every table in the 7d style, percent and signed-change number formats, a dash for a missing figure; a sheet prints landscape only when its columns are wider than a portrait page (none today), which replaces the "more than 4 columns" rule of 7d.
- **Gotcha learned:** MySQL (only_full_group_by) treats `DATE_FORMAT(col, ?)` in SELECT and in GROUP BY as two different expressions when the format is bound, and the security scan (`CodeScansTest`) refuses a variable inside raw SQL. The daily census uses two fixed query texts.

### Performance (7g, decided and built 2026-10-26)
- **Measured first, in both modes.** A busy year was seeded only on `patient_census_test` (`PerformanceSeeder`; it refuses any database not ending in `_test`); every run reloads the same dump. The dev database was only read (Excel / PDF breakdown in a read-only MySQL session). Production mode was measured in a copy of `system/` with its own `.env`, so the real `.env` was never changed. Results and the phase table are in `docs/developer-guide.md`.
- **Indexes (migration `2026_10_26_000002_add_performance_indexes`, only adds three indexes, run on `patient_census` 2026-10-26):** `visits (deleted_at, visited_at)`, `patients (deleted_at, last_name, first_name)`, `audit_logs (action, created_at)`. Every list hides Trash or shows only Trash, so each starts with `deleted_at` and then the sort column. Records, Trash and the Audit log action filter use them.
- **Late pages read ids first (`TablePaging::paginate`):** only the page's ids come from the index, then the 10–50 full rows with their relations and counts. Same rows, order and page numbers as `paginate()` (a test compares them with ties and late pages). Paging itself (10 / 20 / 50, 3 numbers, jump) is unchanged.
- **60-second alert cache (decided 2026-10-26):** the Admin warning bars (backups, test restore, USB copy, audit clean-up, scheduler) come from one cache entry, `AdminAlerts`, valid 60 seconds; the hospital name, subtitle and logo version from `HospitalSettings::shared()`, also 60 seconds. They are forgotten **at once** by a new, changed or deleted backup run, test restore, backup mark (USB copy, test restore) or audit clean-up run (trait `ClearsAdminAlerts` on the four models), by the scheduler beating again after it was stale, and by any `Setting` save. A problem that appears only with time (no backup for 26 hours, a reminder overdue, scheduler silent for 5 minutes) shows within 60 seconds. **A new record type that can turn a bar on or off must use `ClearsAdminAlerts`.** Encoders never run the bar checks.
- **No query per row:** Trash loads "still used?" for Delete permanently with `withExists` (`TrashPolicy::HAS_VISITS` / `HAS_AUDIT`); a page asks "is this month closed?" through `MonthClosure::remembering(...)` (closed months read once, for building a page only, never around close or reopen). Query-count tests fail if a list starts a query per row.
- **Search, same results:** the patient search adds "last name starts with the typed text up to the first space or comma" so the name index is used (the client waits 250 ms and cancels the previous request, 10 results at most); Records > Visits finds the matching patients first, then their visits; the Audit Record filter looks the record's id up first and lists the `.purged` actions instead of `LIKE '%.purged'`. Tests keep the old queries and compare. **A test fails if a `.purged` action exists in the code that the Audit Record filter's list (`AuditRows::purgedActions`) does not contain** (`month.report_purged` ends in `_purged`, never matched the old rule either, and stays out on purpose).
- **Power plan (decided 2026-10-26):** the server's Windows power plan should be **High performance**. On Balanced, Windows moves background processes without a window to the slow power-saving cores of newer processors; the same PHP code ran 3–4 times slower on the dev laptop (an empty route 13 ms fresh, 45–90 ms throttled). It is in `docs/operations-guide.md` (section 11), `docs/requirements.md`, `planning/deployment-handover.md` and `docs/troubleshooting.md` (section 12). The measuring tools opt only their own process out of throttling (`scripts/perf/unthrottle.ps1`); no Windows setting is changed.
- **PDF font subsetting stays off (decided 2026-10-26):** the PDF is 1.3 MB instead of 76 KB, but making it is about 90 ms slower with subsetting. The PDF time is mostly dompdf laying out 23–27 pages (about 1.0–1.4 s); nothing else in it is large.
- **Excel:** already styled by range with fixed widths; now the merged title cells use "hide" mode (nothing to blank), the PDF's small logo is made once per logo file, and Export right after Generate does not count again (tested). Same sheets, 12 native charts, hidden Chart data sheet, same numbers. Monthly / annual production times: Excel 0.31 / 0.34 s, PDF 1.4 / 1.5 s, so the "file is ready" background download was **not** needed and not built.
- **Server settings:** System health **Speed settings** (OPcache, config / route / event caches and log level not debug are Warnings; `public/hot` is a Problem); `census:install` lists OPcache as a requirement (FIX with a pointer to `docs/requirements.md`, which now has the `php.ini` block); install / update build the event cache too. System health remembers `mysql --version` for 10 minutes (0.2 s). Sessions and cache stay in the database; the 01:30 cache clean-up exists and the cache table is indexed; expired sessions are removed by Laravel's own 2 % lottery, so no new job.
- **Static files:** `public/.htaccess` lets browsers keep `public/build/assets` for a year (file names change with every build) and compresses scripts, styles and SVG, never pages or JSON (they carry the sign-in token). The signed-in logo route is cached for a day (`?v=` changes with a new logo); signatures are never cached. Pages were already one chunk each, so bundle sizes did not change (shared 373 KB / 116 KB gzipped, app 118 KB, pages 1–57 KB).
- **Test rules learned:** a Windows checkout turns `app.css` into CRLF, so the 7f contrast test could not find its `@media screen` block; the test now reads both. Shell one-liners that edit PHP broke files twice: use the editor for code changes. Run the whole suite again after any last fix (done).

### Audit log retention (7e, decided 2026-10-21, built 2026-10-26)
- **The audit log keeps 1 year.** This replaces "the audit log is never deleted". Nobody deletes entries by hand (no route, button or model delete; the model still refuses `delete()` and `update()`). Only the automatic job removes entries older than `census.audit.retention_days` = 365 (a config value, not editable in the UI).
- **Archive first, then delete.** `census:prune-audit` runs daily at 04:30 under the backup lock (`BackupService::LOCK`), so it never runs during a backup, a test restore or a USB copy; if the lock is busy it skips that night and records nothing. It writes the old entries to `audit-archive_YYYY-MM-DD.csv.gz` in `BACKUP_PATH` (`.part` file, read back and row count checked, then renamed), and only then deletes exactly those rows in chunks of 1,000, each chunk in its own transaction. A same-day second archive gets `_2`, so an earlier file is never overwritten. If a delete fails after the archive was written, the next run archives the same rows again (they can appear in two files).
- **One `audit.pruned` entry** (count, oldest and newest date, archive file name, no personal data). It is subject to the same 1-year rule later.
- **Archives are kept** (they are small). The 30-day backup cleanup only matches its own `patient_census_*` names, so it never deletes them (tested). **Copy to USB** also copies the newest archive file; older archives already on the USB are left alone.
- **`audit_prune_runs` table** (one row per run: started, finished, status, rows, archive name, message), model `AuditPruneRun`, morph name `audit_prune_runs`. System health and the red bar read the latest row.
- **Quiet success:** when nothing is old enough the run is saved as a success with 0 rows, with no archive file and no audit entry, so the log is not filled with a daily line.
- **Failure:** nothing is deleted; the run is saved as failed; Admin sees a red bar "Audit log clean-up failed: <short error>" (through the same `backupAlerts` banner) until a later run succeeds.
- **System health check "Audit log clean-up"** (16 checks now): OK when the last run succeeded within 2 days; Problem when the last run failed; Warning when it ran more than 2 days ago. **A fresh server shows a Warning until the first run** (04:30 after install), then turns OK.
- **Audit log page:** a note under the title ("Entries older than 1 year are removed automatically (archived to the backup folder)."); a typed From date older than the retention date is moved up to it (server side) and the date pickers have it as their minimum. An empty From still means no limit.
- **Data Privacy:** confirm the 1-year retention with the hospital's Data Protection Officer; the archive files keep older entries if needed (in `planning/deployment-handover.md` and `docs/operations-guide.md`).

## 8. Phase 8 (deployment) notes
- **Server PHP minimum is 8.4.1 (decided 2026-10-19).** `composer.lock` resolved Symfony 8.x packages that need PHP 8.4.1 or newer, and `vendor/composer/platform_check.php` stops the app on anything older (found while building a clean `--no-dev` copy). So `composer.json` now requires `^8.4.1` (lock refreshed), `HealthChecker::MIN_PHP` and `InstallRequirements::MIN_PHP` are 8.4.1 (with their tests), `.github/workflows/tests.yml` runs PHP 8.4, and the docs, `install.bat` requirements check and planning guides say 8.4.1. Re-locking for 8.3 was considered and rejected.
- **MySQL root must have a password (decided 2026-10-19).** A new Laragon starts with root and no password. `census:install` detects that (the root login worked with an empty password) and, before anything else, makes the installer set a new one: asked twice, hidden, at least 12 characters, 3 tries, then it stops with nothing changed. It sets the password on every root account that had none (`ALTER USER`), logs in again with it, and says "Write this in the sealed envelope." The password is only in memory: never in `.env`, `install.log`, the audit log or any file (tested). `census:update` and `census:restore` only warn if root is empty. **System health has a new check, "MySQL root password" (Problem):** the web app cannot read MySQL's account list with its own login, so the check tries one root login with an empty password and stores nothing; if it gets in, it is a Problem with "set a root password of at least 12 characters". It shows on dev PCs that have no root password, which is accurate. Steps to set one on an existing server are in `docs/requirements.md`, "MySQL root password".
- Required PHP extensions include **gd, intl, zip, mbstring, pdo_mysql, fileinfo, openssl**. `gd` is off by default in a fresh `php.ini`; PhpSpreadsheet (Excel export) will not install or run without it.
- The hospital network has **no internet**. Run `composer install --no-dev` and `npm run build` on a dev PC, then copy the `vendor` folder and the built `public/build` assets to the server.
- `storage/` (and `bootstrap/cache/`) must be **writable** by the web server: dompdf font cache, logs and backups live there.
- PDF exports run with remote resources and PHP execution switched off (`isRemoteEnabled` and `isPhpEnabled` false), so the server needs no outside access for them.
- **Set `'serve' => false` in `config/filesystems.php`** (the `local` disk) so Laravel's `storage/{path}` route is not registered (also in `planning/security.md` section 4). Backups are not under that disk, but the route should not exist on the server.
- **PHP upload limits:** set `upload_max_filesize` and `post_max_size` to **at least 2 MB** (the default `upload_max_filesize` is 2M, `post_max_size` 8M). The logo and signature pictures are saved at 1 MB at most; a smaller limit would refuse a valid picture.
- **Sessions and locks need the right drivers:** keep `SESSION_DRIVER=database` (a password reset or change ends other logins by deleting rows in the `sessions` table) and a cache store that supports locks (`CACHE_STORE=database`, file or redis; not `null`), used by the close-month and new-patient locks.
- **Backups cover the database and the pictures (done in 6i-1):** every backup also zips `storage/app/private` (`logo.*`, `signature-*.*`, `frozen-signatures/`). `census:restore` unzips the matching picture zip back; if it is missing, it warns and continues.
- **Backup folder:** set `BACKUP_PATH` in `.env` to the shared folder on the **second PC** (e.g. `//BACKUP-PC/census-backups`, forward slashes). The default `storage/app/backups` is on the same disk as the database, so it is for testing only. The server's Windows account needs write access, and `MYSQLDUMP_PATH` must point to the real `mysqldump.exe`.
